# ADR-0121 개정 A2: 종형님 요약 (2026-10-23)

상태: **비준됨(Ratified)**, 2026-10-23 종형님 확정이에요. 권장안을 모두 그대로 받으셨어요.

- 확정 문구는 헌법(`ARCHITECTURE.md` §5·§8·§10·§12)과 `DECISIONS.md`(ADR-0121 A2, 상태 Accepted)에 넣었어요.
- 종형님 답은 아래 7절에 적었어요.
- 전체 문안은 `docs/plans/adr0121-a2-answer-step-proposal.md`(3차 수정본)에 있어요.
- 코드는 아직 만들지 않았어요. S2가 `active`가 된 뒤에 `QUOKY_AGENT_ANSWER=off` 상태로 만들어요.

## 한 줄 요약

**"조회 + 질문"이 섞인 요청에서 질문에도 답해요.**

- **사실:** 있는지, 몇 개, 몇 시, 빈 시간은 Quoky가 직접 계산해요.
- **일반 지식 질문:** Claude가 **종형님 문장만** 보고 답해요.
- **일정 내용을 봐야 하는 답:** 맥 안의 로컬 모델(qwen3:8b)이 만들어요.
- **새 자료를 만드는 답(면접 질문 등):** 먼저 로컬 모델과 비교 측정해요. **로컬이 부족하고 Claude가 확실히 낫다고 나올
  때만**, 확인하신 **일정 제목 일부**와 종형님 요청 문장을 한 번 Claude에 보내는 길을 열어요.
- 일정 원문은 계속 맥 밖으로 나가지 않아요.

## 1. 왜 필요한가 (10/22 DM)

- **"내일도 면접 있어? AI agent 면접 볼 때 뭐 봐야 할까? 세 가지만"**
  - 결과: 일정만 다시 보여 드리고 질문은 빠졌어요.
  - 이유: 조회 결과 위에서 질문에 답하는 단계가 없어요.
- **"내일 면접 기준으로 면접 질문 좀 뽑아줘"**
  - 결과: 일정 내용을 모른 채 일반적인 답만 했어요.
  - 이유: 일정 내용은 원격 모델로 보내지 않아요(ADR-0110 D4).
  - 이 규칙은 "보안 권고와 맞게"에 따라 **기본값으로 그대로** 둬요.

## 2. 네 가지 답 방식

계획을 짜는 모델이 종형님 말씀만 보고 방식을 골라요. 문구 목록은 하드코딩하지 않아요.

1. **사실만:** Quoky가 계산해요. 모델은 쓰지 않아요.
2. **말씀만으로 답:** Claude가 종형님 문장만 보고 답해요. 답 위에 "일정 내용은 보지 않고 일반적으로 답했어요."라고 표시해요.
3. **목록 안에서 고르기·비교·순서 정하기:** 맥 안의 로컬 모델이 답해요.
4. **일정 하나를 바탕으로 새로 만들기:** 아래 예시 4처럼 처리해요.

공통으로 지키는 것:

- **시간:** 모델은 시간을 직접 쓰지 못해요. 시간은 Quoky가 일정에서 꺼내 넣어요(측정에서 모든 모델이 빈 시간 계산을 틀렸어요).
- **링크:** 어떤 답에도 링크를 넣지 않아요. 링크는 Quoky가 만든 일정 목록에만 나와요.

## 3. DM 예시: 맥 밖으로 무엇이 나가나

**예시 1: 사실 + 일반 질문**
> 종형님: 내일도 면접 있어? AI agent 면접 볼 때 주로 뭐 봐야 할까? 세 가지만
> Quoky: (내일 면접 일정) / 네, 내일 면접 일정이 있어요. / 일정 내용은 보지 않고 일반적으로 답했어요. ① … ② … ③ …

- **나가는 것:** 종형님 문장만 Claude로 가요.
- **안 나가는 것:** 일정 제목과 시간, 면접이 있다는 사실.

**예시 2: 목록 안에서 고르기**
> 종형님: 다음 주 회의 중에 준비가 제일 많이 필요한 거 하나만 골라줘
> Quoky: (회의 목록) / 10월 29일(목) 15:00 고객 미팅이 준비가 가장 많이 필요해 보여요. 이유: …

- **나가는 것:** 없어요. 로컬 모델이 답하고, 날짜와 시간은 Quoky가 넣어요.

**예시 3: 비는 시간**
> 종형님: 오늘 퇴근 전까지 비는 시간 있어?
> Quoky: 오늘 비는 시간: 14:00–15:30, 16:30–18:00

- **나가는 것:** 없어요. 모델 없이 계산해요.
- 이 기능은 "그날 일정 비어 있는지" 조회 기능(A1-D14)이 먼저 만들어진 뒤에 켜져요.

**예시 4: 면접 질문 만들기**
> 종형님: 내일 면접 기준으로 면접 질문 좀 뽑아줘

- **처음에는 로컬 모델이 답해요.** 나가는 것은 없어요.
- **측정에서 로컬이 부족하고 Claude가 확실히 낫다고 나올 때만** 이렇게 여쭤봐요(문구는 종형님 결정 사항):
  > 'AI Agent 1차 면접'이라는 주제(일정 제목 일부)와 요청 문장을 Claude에 보내려고 해요. 이름·회사명이 남아 있으면 '아니'라고 해 주세요. 보낼까요? (응/아니)
- **"응"이라고 하시면:**
  - 나가는 것: `AI Agent 1차 면접`과 "내일 면접 기준으로 면접 질문 좀 뽑아줘", **딱 한 번**이에요.
  - 안 나가는 것: 지원자 이름(예: "홍길동"), 시간, 장소, 참석자, 설명, 링크, 다른 일정, 대화 기록.
- **"아니"라고 하시면:** Quoky가 일정을 다시 읽고 로컬 모델로 답해요.

## 4. 절대 나가지 않는 것

- **일정 원문:** 제목 전체, 설명, 장소, 참석자, 회의 링크, 시간.
- **확인받지 않은 주제.**
  - 받는 답: 정확히 "응·네·예·yes" 또는 "아니·아니요·아니오·아뇨·취소·no"만 받아요.
  - 받지 않는 답: "어", "ㅇㅇ", "y" 같은 말이에요.
  - 다른 말을 하시거나 10분이 지나면 취소되고, 아무것도 안 나가요.
- **대화 기록에 남는 것:** 확인 질문, 보낸 주제, 만든 답, 계산한 사실(시간·빈 시간 등)은 기록에 남기지 않아요.
  "Quoky가 확인받은 주제로 답을 보여드림" 같은 고정 표시만 남겨요.

## 5. 안전장치와 한계

- **주제를 만드는 방식**
  - 제목 단어 중에서 **고르기만** 해요. 30자, 4단어 이하예요.
  - 참석자·주최자·종형님 이름에서 두 글자만 겹쳐도 그 단어는 빼요(예: "길동님"). 이메일, 링크, 세 자리 이상 숫자도 빼요.
    필요한 단어가 가끔 함께 빠질 수 있지만, 덜 보내는 쪽을 택했어요.
  - 그 밖의 이름은 로컬 모델이 걸러요.
- **받는 곳**
  - "학습에 쓰지 않음"이 확인된 원격 모델에만 보내요.
  - 켜기 전에 종형님이 **Claude 계정의 데이터 보관·학습 설정을 직접 확인**해 주셔야 해요. 확인 결과를 기록한 뒤에만 설정으로
    켜고, 설정만 지우면 바로 끌 수 있어요. 계정이나 제공자가 바뀌면 다시 확인해요.
  - 대신 쓰는 예비 모델(fallback)로는 보내지 않아요.
- **횟수와 범위**
  - DM에서만 돼요. 시간당 5회, 하루 20회까지예요.
  - `에이전트 중지`를 보내면 기다리던 확인이 모두 취소돼요.
- **기록:** 주제 자체는 남기지 않고 **키 기반 지문(HMAC)**만 남겨요. 새로 접속하는 서버는 없어요.
- **한계(꼭 알아 두실 것)**
  - 공격 테스트의 "성공 0건"은 **참석자 목록에 없는 이름까지는 보장하지 못해요.**
  - 그 부분은 종형님(또는 분류기 문구를 모르는 별도 세션)이 만든 이름 100개 이상으로 3번 측정해요. 모양별(두·세·네 글자,
    호칭, 영문 등) 90% 이상, 전체 98% 이상 걸러야 해요. 놓친 이름은 목록으로 보고드려요.
  - 측정 기간에 만들어질 뻔한 주제는 DM에서 종형님이 직접 보고 평가하실 수 있어요(메모리에만 두고 저장하지 않아요).

## 6. 감수하실 위험

1. **주제와 요청 문장이 Anthropic 기록에 남아요.** 일정에서 나온 글자가 원격 모델로 가는 첫 사례예요. 보관·학습 여부는 계정
   설정에 달려 있어요.
2. **참석자 목록에 없는 이름은 놓칠 수 있어요.** 두 글자 이름, 영어 이름, 별명 같은 경우예요. 질문 문장을 꼭 봐 주세요.
3. **이름이 없어도 민감한 제목이 있어요.** 인사 면담, 건강검진, 인수합병, "Falcon 킥오프" 같은 코드명은 필터가 판단하지
   못해요. 이런 건 '아니'라고 해 주세요.
4. **로컬 모델 답은 얕거나 틀릴 수 있어요.**
5. **확인이 반복되면 습관적으로 "응"하게 돼요.**
6. **메모리와 시간이 더 들어요.** 메모리 약 5GB, 답마다 3–7초가 더 걸려요.
7. **만든 답은 기록에 남지 않아요.** 그래서 "2번 질문 더 자세히" 같은 이어 묻기는 다시 조회해서 답해요.
