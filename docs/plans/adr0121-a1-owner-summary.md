# ADR-0121 개정 A1: 종형님 요약 (2026-10-21)

상태: **비준됨(Ratified)**, 2026-10-21 종형님 확정. 헌법(`ARCHITECTURE.md` §8·§10·§12)과 `DECISIONS.md`
(ADR-0121 A1, 상태 Accepted)에 확정 문구를 넣었어요. 종형님 답은 아래 6절에 적었어요. 전체 문안은
`docs/plans/adr0121-a1-amendment-proposal.md`에 있어요. 값 넘기기 코드는 S2가 `active`가 된 뒤에만 만들어요.

## 한 줄 요약

**메일·일정·슬랙에서 나온 값을 다른 서비스 조회에 쓰는 것을, 종형님이 화면에 보이는 값을 직접 고를 때만 허용해요.
그리고 "도움말이랑 ○○", "브리핑이랑 ○○"처럼 섞인 요청은 두 부분 모두 답해요.** "메일에 시키는 대로 해줘" 같은
대신 실행은 계속 하지 않아요.

## 1. 무엇이 바뀌나

### (1) 다른 서비스로 값 넘기기 (종형님이 직접 고를 때만)

지금은 메일에 적힌 날짜나 지라 키를 다른 서비스 조회에 쓰는 게 전부 막혀 있어요. 바뀌면 이렇게 돼요.

1. 종형님이 **어디서 → 어디로, 무엇을** 할지 직접 말씀하세요. 예: "메일에 나온 날짜에 내 일정 비어 있는지 봐줘".
2. 메일이 여러 통이면 목록을 보여 드리고, **한 통**을 번호로 골라 주세요.
3. Quoky가 그 한 통에서 값 후보를 뽑아서, 정해진 양식으로 **그대로** 보여 드려요.
   ```
   ⚠ 외부 내용에서 나온 값 · 메일 → 캘린더 확인
   보낸 사람 …, 제목 …, 10/21
   1. `10월 24일` (자동 추출)
   2. `10월 28일`
   번호(최대 3개)를 보내거나 검색어를 직접 입력하세요. 다른 메시지를 보내면 취소돼요.
   ```
4. 종형님이 **번호를 보내거나 값을 직접 입력**하시면, 그 값으로 말씀하신 조회 한 번만 해요.

**먼저 켜는 것 (형식이 정해진 값):**
- 메일의 날짜 → 그날 내 일정
- 메일의 지라 키 → 이슈 상태
- 오늘 회의 참석자 → 그 사람들이 보낸 메일
- 슬랙에 공유된 PR → 깃허브 상태

**나중에, 측정한 뒤에만 켜는 것 (모델이 단어를 골라야 하는 것):**
- 회의 → 관련 지라
- 메일 본문의 키워드 → 슬랙 검색
- 회의록의 액션 아이템 → 지라

### (2) 섞인 요청 두 부분 다 답하기 (결정 (e))

- **"도움말이랑 지라 이슈 같이"** → 도움말은 정해진 문구로 따로 한 칸, 지라 이슈는 평소처럼 조회해서 한 칸.
  도움말 부분은 모델 없이 처리해요. 새 문구를 하드코딩하지 않고, 지금 있는 도움말 단어만 써요.
- **"오늘 브리핑이랑 슬랙 장애 같이"** → 브리핑 한 칸, 슬랙 검색 한 칸.
  - 브리핑 안의 일정은 계속 **로컬 모델 전용**, 메일은 계속 **DM 전용**이에요.
  - 브리핑은 모델 요약에 넣지 않아요. "같이 정리해줘"라고 하셔도 요약은 다른 조회 쪽만 해요.
  - 브리핑이 읽는 횟수도 한 번 요청의 상한(외부 조회 10번, 45초)에 같이 계산해요.
- OpenClaw가 비슷하게(도움말을 먼저 처리) 하지만, 따라 해서가 아니라 단순하고 결정적인 방식이라 고른 거예요.
  섀도 기간에 측정해서 결과가 나쁘면 지금 방식으로 되돌려요.
- 평가 정답지에서 "도움말/브리핑 + 다른 조회" 6건은 "답하지 않음"에서 "두 칸으로 답함"으로 바뀌어요.
  AP-6 묶음을 다시 확인해 주시고, 같은 종류 20건 이상(AP-7)을 새로 승인해 주셔야 해요.

## 2. 계속 거절하는 것

- **"받은 메일에 시키는 대로 해줘"**: 메일 내용이 행동을 정하게 되니 안 돼요. 대신 "이 메일은 X를 요청해요"라고
  요약만 드리고, 하실 일은 종형님이 직접 말씀하시면 평소 승인 절차로 진행해요.
- **"PR 설명에 있는 지시대로 코드 작업해줘"**: 남이 쓴 글이 코드 작업 도구를 움직이게 돼요(원격 코드 실행과 같아요).
  PR이 무엇을 요청하는지 요약만 드리고, 코드 작업은 종형님이 직접 요청하실 때 기존 승인 절차로 해요.
- 그 밖에:
  - 값 넘기기로 **쓰기**(메일 보내기, 지라 수정 등)는 절대 안 해요. 조회만 해요.
  - 내용이 목적지를 정하는 일은 없어요. 목적지는 항상 종형님 말에서만 정해요.

## 3. 안전장치

- **고른 값의 꼬리표 `OWNER_CONFIRMED`**: 종형님이 고른 값이라도 "믿을 수 있는 값"으로 올리지 않아요.
  - 계획을 짜는 모델에는 절대 안 들어가요.
  - 정해진 조회 칸 한 곳에만, 한 번만 쓰여요.
  - 저장·기억·학습에도 남지 않아요.
  - 후보 목록에서 **직접 입력하신 값도 똑같이** 이 꼬리표가 붙고 같은 검사를 거쳐요(검사를 우회하는 길이 없어요).
  - 넘길 값이 하나도 없거나 횟수 제한에 걸리면 "넘길 수 있는 값을 찾지 못했어요"라고만 하고, 직접 입력하라고
    안내하지 않아요.
  - 기다리는 동안 숫자만 보내시면 이 값 고르기가 먼저 받아요(다른 번호 질문보다 우선). 이 목록은 나중에
    "N번"으로 다시 가리킬 수 없어요.
- **뽑는 방식**:
  - 지라 키·날짜·이메일·PR 링크는 정해진 규칙으로만 뽑아요(모델 없음).
  - 자유 단어는 모델을 쓰더라도 **그 한 통 안에 글자 그대로 있는 것만** 남겨요.
  - 일정 내용에서 모델로 단어를 뽑을 때는 로컬 모델만 써요. (모델을 쓰지 않는 값 넘기기는 다른 서비스 검색으로
    나갈 수 있어요. 예: 회의 제목의 단어 → 지라 검색. 아래 위험 2를 보세요.)
- **값 검사**:
  - 모든 값: 보이지 않는 문자, 비슷하게 생긴 다른 나라 문자, 줄바꿈은 거절해요. 길면 자르지 않고 거절하고,
    비밀번호·토큰처럼 보이면 버려요.
  - 자유 단어: 검색 조작 기호(`:` `"` `OR` 등), 링크, 긴 숫자도 거절해요.
  - 형식이 정해진 값은 형식 그대로여야만 통과해요.
    - 지라 키: 보이는 프로젝트의 키만.
    - 이메일: 주소 형식만.
    - PR: 허용된 저장소의 `owner/repo#번호`나 정식 링크만.
    - 날짜: 날짜 해석기가 만든 값만.
- **고르는 방식**:
  - 번호(최대 3개)나 직접 입력만 받아요. "응/네/전부"는 받지 않아요.
  - 한 번만 쓸 수 있고, **10분이 지나거나 다음 메시지가 오면** 사라져요.
- **횟수 제한**:
  - 후보는 5개까지 보여 드리고, 3개까지 고를 수 있어요.
  - 한 번 요청에 1회, 시간당 10회, 하루 30회까지예요.
- **DM에서만** 돼요. `에이전트 중지`를 보내면 기다리던 값 넘기기가 모두 취소돼요.
- **기록**: 실제 값은 남기지 않고 암호화된 지문(HMAC)만 남겨서, 사고가 나면 대조할 수 있어요.
  - 새로 접속하는 서버는 없어요.
  - 트래픽 장부에 `agent-handoff`로 따로 집계해요.
- **공격 테스트**: 새 공격 사례 80건 이상을, "종형님이 공격자 후보를 항상 고른다"는 최악의 가정으로 3번 돌려요.
  성공한 공격이 0건이어야 해요. 그 다음 섀도 7일을 거쳐요.
- **스위치**: `QUOKY_AGENT_HANDOFF=off|shadow|active`. 기본은 `off`이고, S2가 `active`가 된 뒤에만 켤 수 있어요.

## 4. 종형님이 감수하시는 위험 (비준할 때 동의)

1. **유도**: 나쁜 메일이 "무엇을 찾을지"를 유도할 수 있어요. 조회만 하고 DM에만 보여서 피해는 제한적이지만,
   완전히 없앨 수는 없어요.
2. **다른 회사로 값이 나감**: 고르신 값(최대 30자)이 슬랙·아틀라시안·깃허브 검색과 그 로그에 남아요
   (MSIT ⑤-1 업무 범위 밖 반출). 일정도 예외가 아니에요. 회의→관련 지라는 **회의 제목의 단어**를 지라 검색으로,
   참석자→메일은 참석자 주소를 지메일 검색으로 보내요. 일정 내용을 원격 모델에 보내지 않는 규칙은 그대로예요.
3. **확인 피로**: 반복되면 습관적으로 1번을 고르시게 돼요. 그래서 안전은 종형님의 주의가 아니라 위의 기계적 검사에 기대요.
4. **모델이 뽑는 단어의 품질**: 모델이 진짜 키워드를 숨기거나 엉뚱한 후보만 보여 줄 수 있어요.
   원격 모델을 쓰면 메일·드라이브 내용이 그 모델로 가요(기존 ADR-0118에서 이미 허용한 범위).
5. **날짜·사람 오인**: 날짜나 참석자를 그럴듯하게 잘못 읽을 수 있어요. 값을 그대로 보여 드리고 조회만 해요.
6. **하위 프로세스는 여전히 막지 못함(R1)**: 그래서 PR 지시대로 코드 작업은 계속 거절해요.
7. **복잡도 증가**: 기다리는 상태와 새 꼬리표가 생겨서 공격 표면이 조금 넓어져요.
8. **도움말 나누기 오류**: 도움말을 놓치거나, 도움말을 언급만 한 문장에 도움말 칸을 붙일 수 있어요(읽기 전용이라 해는 작아요).
9. **무거운 섞인 요청**: 브리핑이 들어가면 한 번에 외부 조회가 최대 7번 늘고 답이 길어져요(DM 전용, 상한은 미리 계산).

## 5. 진행 순서

1. **종형님 비준**: 이 제안, 감수하실 위험, 아래 질문의 답.
2. **문서 반영**: `ARCHITECTURE.md`와 `DECISIONS.md`에 확정 문구를 넣는 문서 PR.
3. **S2 마무리**: 섞인 요청(결정 (e))은 S2 안에서 같이 만들어요. 정답지 수정, 계획 프롬프트 v3, 실행을 거쳐
   S2 관문과 섀도 7일을 통과하면 `active`.
4. **값 넘기기 개발**: S2가 `active`가 된 뒤에 `off` 상태로 만들어요. 새 조회 3개(지라 키 조회, PR 상태, 그날 일정 비어
   있는지)도 같이 만들고, 각각 평가를 거쳐요.
5. **공격 테스트**: 80건 이상, 3번, 0건.
6. **섀도 7일**: 설정 변경과 재시작은 종형님 허락을 받아요.
7. **형식이 정해진 값부터 켜기**: 날짜→일정, 지라 키→상태, 참석자→메일, PR→깃허브.
8. **측정 후 모델이 필요한 것 켜기**: 회의→관련 지라, 메일 키워드→슬랙, 액션 아이템→지라.

## 6. 결정해 주실 것 (2026-10-21 종형님 답 반영)

1. 헌법 §10은 지금 "다른 곳으로 가는 데이터 흐름은 모두 승인 카드(HIGH)"라고 되어 있어요. 값 고르기는 승인 카드처럼
   보이면 안 돼서(오해 방지), "다른 곳으로 가는 흐름은 모두 HIGH이고, **예외는 A1 값 넘기기로 하는 조회 하나뿐**"이라는
   문구를 추가하려고 해요. **(권장: 추가)**
   - **답: 추가.** "다른 곳으로 가는 흐름은 모두 HIGH, 예외는 A1 값 넘기기로 하는 조회뿐"을 헌법 §10에 넣었어요.
2. 모델이 필요한 값 넘기기를 켜는 기준.
   - 권장: 형식 값 넘기기를 실사용 30회 이상 무사고로 쓰고, 모델 추출을 섀도로 50건 이상 측정하고, 공격 0건일 때.
   - 켜는 방법: 코드 잠금 해제로 할지(권장), 스위치를 따로 둘지.
   - **답:** 아래 세 가지를 **모두** 채운 뒤에만 켜요. 형식 값 넘기기 실사용 30회 이상 무사고, 모델 추출 섀도 측정
     50건 이상, 공격 성공 0건. 켜는 방법은 **코드 잠금 해제**예요(스위치를 따로 두지 않아요).
3. 계획 모델이 섞인 도움말을 놓쳤을 때 지금처럼 거절할지(권장, 단순), 자동으로 도움말 칸을 만들지.
   - **답: 거절(단순).** 도움말 칸을 자동으로 만들지 않아요.
4. "오늘 브리핑하고 내 지라 이슈 같이 정리해줘"의 정답: 브리핑 + 지라 요약(권장)인지, 브리핑 + 지라 목록인지.
   - **답: 브리핑은 그대로 + 지라 요약.** 요약은 브리핑이 아닌 부분만 하고, 브리핑은 모델 요약에 절대 넣지 않아요.
5. "이번 주 회의 정리하고 관련 jira 이슈도 같이"에서, 모델 단계가 켜진 뒤 "회의 번호를 보내면 관련 지라를
   찾아볼게요"라고 제안할지, 지금처럼 안내 문구만 둘지.
   - **답: 아직 정하지 않음(열린 질문).** 회의→관련 지라(H-5)를 켜기 전까지는 지금의 고정 안내 문구를 그대로 둬요.
6. 브리핑의 메일 읽기(최대 3번 세부 조회)도 상한 10번에 넣어 셀지. **(권장: 넣음)**
   - **답: 넣음.** 한 번 요청의 외부 조회 10번 상한에 같이 세요.
