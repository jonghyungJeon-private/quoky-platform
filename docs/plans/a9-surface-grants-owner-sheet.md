# ADR-0122 (A9) — 채널 권한 허용: 소유자 결정 시트 (2026-10-15)

상태: **승인됨(Accepted, 2026-10-15)** — 종형님 답 "모두 권장안 (권장)": 결정 1–11, 13, 14 모두 권장안대로(12는 해결됨).
"기억 새는 문제"는 P0 핫픽스(#219)로 먼저 나갔고, **P1**(관문·분류·저장 잠금·사전 허용·끄기 스위치·권한 보기/해제)은 브랜치
`claude/v5-surface-grants`에 구현됐습니다. 배포 순서상 코드 기본값은 `off`이고, 종형님이 운영 `.env.local`에
`QUOKY_CHANNEL_GRANTS=enforce`와 아래 사전 허용 값을 넣어 주시면 켜집니다(Strict, 따로 여쭙니다). P1에서는 "허용" 문장은
아직 "준비 중" 답만 하고(P2), 권한 해제·보기·비상 정지는 됩니다. 근거와 전체 문구는 `DECISIONS.md`의
"ADR-0122 — Surface permission grants"에 있습니다.

## 한 줄 요약

**DM은 지금처럼 다 됩니다. 채널에서는 종형님이 그 채널에 직접 허용한 묶음만 답하고, 나머지는 "권한 없음"으로 답하며
아무것도 읽지 않습니다.** 지금 테스트하는 QA 채널(`#일반`)은 배포할 때 지금 되는 묶음을 미리 허용해 둬서 테스트가
깨지지 않습니다.

## 왜 필요한가

- 채널에는 종형님만 말을 걸 수 있습니다(다른 사람·봇 메시지는 어댑터가 버림). 위험은 **명령**이 아니라 **노출**입니다.
  종형님이 채널에서 물어본 Jira·캘린더·Slack 검색 결과는 그 채널을 보는 사람 모두에게 보입니다.
- 새로 만드는 `jira.release`(릴리스 전체 담당 조회)는 다른 사람 담당 이슈까지 보여 주므로, 서버 전체가 보는 `#일반`
  같은 곳에서는 더 조심해야 합니다.
- 지금은 "DM에서만" 규칙이 메일·드라이브·브리핑·자연어 실행 핸들러 안에 따로따로 들어 있고, 카탈로그의 `dmOnly`
  표시는 실제로 아무 코드도 읽지 않습니다. 새 기능이 생기면 기본으로 채널에 열려 버리는 구조입니다.
- 하나 더 찾은 것: **DM에서 "기억해:"로 저장한 기억이 채널 대화에서도 떠올려집니다**(ADR-0073 개정의 소유자 단위
  기억). **P0 핫픽스로 먼저** 모든 채널에서 끄고, A9 후에는 "기억" 묶음을 허용한 채널에서만 다시 켭니다(결정 8).
- MSIT 보안강화 권고(#ax-security) ⑤-1 "응답에 필요한 최소 데이터만"과 맞춥니다.

## 무엇이 바뀌나

### 묶음(그룹) 목록

| 묶음 | 채널에서 | 무엇이 들어 있나 |
|---|---|---|
| 대화, 도움말, 제어 | **항상 됨** | 일반 대화, 도움말, 모델 상태/변경, 새 대화, 권한 명령, 승인 답변 |
| Jira 내 담당 조회 | 허용해야 됨 | 내 담당·내가 보고한 이슈, 이번 주 마감, 키워드. "Jira"라고만 하면 이 묶음 |
| Jira 프로젝트·릴리스 조회(전체 담당) | 허용해야 됨 (강함) | 릴리스 전체 담당 이슈, 프로젝트 릴리스 목록 |
| GitHub 조회 | 허용해야 됨 | 내 PR·이슈, 리뷰 요청, 코드 작업 중 PR 상태 확인 |
| Slack 검색 | 허용해야 됨 (강함) | Slack 검색 (비공개 채널·DM 메시지도 나올 수 있음) |
| Confluence 검색 | 허용해야 됨 | Confluence 검색 |
| 캘린더 조회 | 허용해야 됨 | 일정 조회 |
| 할 일 | 허용해야 됨 | `할 일 추가:` 등 정확한 명령, 할 일 목록 |
| 알림 | 허용해야 됨 | 알림 등록·취소·목록, 채널로 알림 받기 |
| 기억 | 허용해야 됨 | `기억해:`, 기억 목록, 보관함, 피드백 후보·예시, 👍/👎 반응 기록, 그리고 대화 중 기억 떠올리기 |
| 코드 작업 | 허용해야 됨 (강함) | 코드 변경·적용, 커밋, push, PR 생성, merge, main 동기화, 브랜치 정리(원격 포함), 프로젝트 등록·분석·테스트. push·PR·merge·원격 브랜치 삭제는 GitHub 쓰기라 강한 묶음 |
| 외부 쓰기(승인) | 허용해야 됨 (강함) | Jira 댓글·상태·이슈 생성, Slack 게시, 캘린더 등록·변경·취소 (승인 카드가 채널에 보임). **그 서비스의 조회 묶음도 함께 허용돼 있어야** 합니다(미리보기에 그 서비스 내용이 보이므로) |
| 메일, 드라이브, 브리핑, 자연어 실행, 에이전트 | **채널 불가 (DM 전용)** | 지금도 DM 전용. 허용 명령으로도 못 엽니다 |

- "내 할 일" 합쳐 보기(할 일 + Jira + GitHub)는 어느 길로 들어오든(명령·자연어·"내 업무" 질문) **할 일** 묶음으로 답하고, Jira·GitHub 부분은 그 묶음도 허용된
  채널에서만 읽습니다. 아니면 "Jira·GitHub 항목은 이 채널에서 허용되지 않아 뺐어요" 한 줄로 대신합니다.

### 채널에서 쓰는 명령 (정확한 문장만, 종형님만)

- **허용:** `이 채널에 Jira 내 담당 허용` (여러 개는 쉼표: `이 채널에 캘린더, GitHub 허용`)
  → 바로 허용하지 않고 한 번 확인합니다:
  > 이 채널(#일반)에 다음을 허용할까요? · Jira 내 담당 조회 — 이 채널을 볼 수 있는 사람은 모두 답을 볼 수 있어요.
  > 서버 인원 최대 N명 · 비공개 채널: 아니요. 허용하려면 2분 안에 "허용 실행"이라고 보내 주세요. 다른 말을 보내면 취소돼요.
  - 강한 묶음은 경고 한 줄이 더 붙습니다(Slack: "비공개 채널·DM 메시지도 나올 수 있어요", Jira 전체: "다른 사람 담당
    이슈도 보여요", 외부 쓰기: "승인 카드에 보낼 내용 전체가 보여요").
  - 인원 수는 서버 전체 인원(상한)입니다. 채널별 정확한 인원은 Discord의 특권 권한이 필요해서 받지 않습니다(최소 권한).
- **확인:** `이 채널 권한 보여줘` → 허용된 묶음, 허용한 날, "직접" / "배포 시 사전 허용", 그리고 DM 전용 목록.
- **해제:** `이 채널에 Jira 내 담당 허용 해제`, `이 채널 권한 모두 해제` → 확인 없이 바로 해제(노출이 줄기만 하므로).
- **DM에서:** `채널 권한 목록` (모든 채널), `모든 채널 권한 해제` (비상용).
- **비상 정지:** `에이전트 중지`(DM) → 모든 채널 권한이 **멈춤**(지워지진 않음). `에이전트 재개`로 돌아옵니다.
- 허용·해제할 때마다 종형님 DM에 한 줄 기록이 갑니다(누가 종형님 Discord 계정으로 몰래 허용해도 바로 보이게).
- 승인해 둔 작업도 **실행하는 순간에 다시 확인**합니다. 승인 후 권한을 해제했다면 "실행" 문장을 보내도 실행되지 않습니다.
- 권한 저장은 한 번에 하나씩만 쓰도록 잠금을 둡니다. 그래야 다른 설정 저장이 방금 해제한 권한을 되살리지 않습니다.

### 권한이 없을 때 답

> 이 채널에서는 'Jira 내 담당 조회' 권한이 없어요. 아무것도 읽지 않았어요. DM으로 물어보시거나, 이 채널에 허용하려면
> "이 채널에 Jira 내 담당 조회 허용"이라고 보내 주세요.

메일·드라이브·브리핑·자연어 실행은 지금과 똑같은 "DM에서만 답해요" 문구 그대로입니다.

### 배포할 때 QA 채널 사전 허용 (명시·기록·승인)

- 설정 한 줄(`QUOKY_CHANNEL_GRANTS_SEED`)로 **QA 채널(#일반, 1520835639904309350)** 에 다음을 미리 허용합니다:
  Jira 내 담당, Jira 프로젝트·릴리스, GitHub, Slack 검색, Confluence, 캘린더, 할 일, 알림, 기억, 코드 작업.
  (지금 그 채널에서 되는 조회·로컬 작업 + 곧 테스트할 Jira 릴리스. **외부 쓰기는 빼고**, 쓰기 테스트할 때만 문장으로
  허용했다가 끝나면 해제합니다.)
- 시작할 때 **한 번만** 적용되고(소유자 계정 연결이 끝난 뒤), 로그 한 줄과 종형님 DM 한 줄("배포 시 사전 허용: …")이
  남습니다. 나중에 종형님이 해제한 묶음은("모든 채널 권한 해제" 후에도) 같은 값으로는 다시 살리지 않습니다. 설정 값을
  **바꾸면** 해제했던 묶음이 다시 들어갈 수 있는데, 그때는 DM으로 "해제하셨던 …을 다시 허용했어요"라고 분명히 알립니다. 허용 목록에 없는 채널이나 DM 전용 묶음을 적으면 시작이 멈춥니다.
- 비상시 `QUOKY_CHANNEL_GRANTS=off`로 오늘과 완전히 같은 동작으로 되돌릴 수 있습니다.
- **배포 전 확인:** "에이전트 중지"가 이미 켜져 있으면 사전 허용까지 포함해 채널 권한이 처음부터 모두 멈춥니다. 배포 전에
  확인해서 종형님께 알리고, "에이전트 재개"를 할지 정합니다.

### 바뀌지 않는 것

- DM(텔레그램, 디스코드 DM)은 오늘과 글자 하나까지 같습니다.
- 다른 사람이 채널에서 말하면 지금처럼 아예 무시합니다(답도 기록도 없음).
- 마이그레이션 없음: 권한은 기존 소유자 정보(`Actor.metadata`)에 저장합니다(자연어 선호, 에이전트 중지 스위치와 같은 곳).

## 결정해 주실 것 (권장안 먼저)

1. **ADR-0122 채택** (채널 기본 거부, 하나의 관문, 채널·묶음별 허용). **권장: 채택.**
2. **묶음 목록과 분류** (허용 가능 11개, 항상 3개, DM 전용 5개). **권장: 위 표대로.**
3. **허용은 정확한 문장 + "허용 실행" 확인(2분)만**, 자연어로는 허용 안 됨. **권장: 그렇게.** 노출을 넓히는 일은
   모델이 고르면 안 되기 때문입니다.
4. **Jira 내 담당 / Jira 전체(프로젝트·릴리스)는 따로 허용**, "Jira"만 쓰면 내 담당. **권장: 그렇게.**
5. **외부 쓰기(승인)** — 채널에서도 허용 가능하되 기본 거부 + 강한 경고 + 그 서비스 조회 묶음도 필요. QA 채널 사전
   허용에는 **넣지 않고**, 쓰기 테스트 때만 문장으로 허용 후 해제. 다른 안: 채널에서는 아예 불가. **권장: 허용 가능,
   사전 허용 제외.**
6. **만료 기간** — 없음(해제할 때까지 유지). 다른 안: 30일/90일 자동 만료. **권장: 없음.**
7. **에이전트 중지 = 채널 권한 전체 멈춤**(재개하면 복구). **권장: 예.**
8. **기억 묶음이 없는 채널의 대화에서는 저장된 기억·예시를 떠올리지 않음.** **권장: 예.** (지금은 DM 기억이 채널
   대화에 섞일 수 있음. 모든 채널에서 끄는 P0 핫픽스가 먼저 나갑니다)
9. **채널에서도 의도 판단은 전체 기능을 보고**, 권한 없는 요청에는 정직하게 "권한 없음"으로 답함. **권장: 예.**
10. **허용·해제 때마다 DM 기록 한 줄.** **권장: 예.**
11. **QA 채널 사전 허용 값**(위 10개 묶음, 외부 쓰기 제외). **권장: 그대로 승인.**
12. (해결됨) Jira 릴리스 조회는 A8 승인대로 기본이 "내 담당"입니다. 내 담당 + 릴리스 이름 → "Jira 내 담당",
    릴리스 목록이나 전체 담당 → "Jira 전체". 번호만 유지합니다.
13. **권한을 줄 수 있는 채널은 최대 16개.** **권장: 승인.**
14. **되돌리기 스위치** `QUOKY_CHANNEL_GRANTS=enforce|off`, 기본 enforce, 그림자 모드 없음. **권장: 승인.**

## 알려 드릴 한계

- **채널 인원은 상한만** 보여 드립니다(서버 전체 인원). 허용한 뒤에 채널이 다른 카테고리로 옮겨지거나 권한이 바뀌어
  보는 사람이 늘어도 Quoky는 알지 못합니다. `이 채널 권한 보여줘`로 가끔 확인해 주세요.
- 스레드는 부모 채널의 권한을 그대로 따릅니다(지금 입장 규칙과 같음).
- 종형님 Discord 계정이 탈취되면 그 사람도 "종형님"입니다. DM 기록과 `에이전트 중지`로 줄이고, 메일·드라이브는 어떤
  경우에도 채널에서 열리지 않습니다.

## 구현 규모와 승인이 따로 필요한 일

- 승인 후 구현 약 **7~8일** 분량, 단계로 나눕니다(일부 기능만 먼저 막는 방식은 다른 길이 열린 채로 남아 위험해서 안 함):
  - **P0** (지금, 별도): 채널 대화에서 저장된 기억 떠올리기 끄기.
  - **P1** (~4일): 관문 + 모든 핸들러·코드 작업 단계 분류, 저장 잠금, 사전 허용, 끄기 스위치, 권한 보기·해제. 이것만으로도
    안전하게 배포 가능(새 허용은 사전 허용으로만).
  - **P2** (~2~3일): "허용" 문장과 "허용 실행" 확인, 인원 안내, 합쳐 보기 필터, 채널 알림 전달 확인, DM 기록.
- merge 전에 Chief Architect 리뷰가 필요합니다(핸들러 포트와 런타임 분기 변경).
- **따로 승인 필요(Strict):** Push·PR·Merge, 상시 서비스 재시작, 운영 `.env.local`에 스위치·사전 허용 값 넣기, 사전
  허용의 첫 적용(운영 DB의 소유자 정보 변경), QA 채널 실사용 테스트. 마이그레이션과 비밀 값 접근은 없습니다.
