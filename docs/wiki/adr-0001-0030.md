# ADR summary 0001-0030 (v1 foundations, v2 Sprint 2a-2i capabilities)

Pointer for every entry: `DECISIONS.md`, heading `## ADR-NNNN` (find with `grep -n '^## ADR-NNNN' DECISIONS.md`, then read only that range). Status is as stated in the ADR; "accepted" = the ADR's Status line says Accepted. Reason "see ADR" = no brief reason in the ADR's opening lines. Early ADRs mention `@chunsik/*` packages; the scope was later renamed `@quoky/*`.

| ADR | Decision (one line) | Reason (one line) | Status |
|---|---|---|---|
| 0001 | Session is a thin conversation aggregate (id, context, actorId, projectId, status, activeTaskId); no snapshots stored in it | Every Task/memory scope is anchored to a conversation; a fat Session becomes a god object | accepted (v1) |
| 0002 | ContextBuilder is a separate service returning a ContextBundle; it never writes files | Keeps memory CRUD (system of record) apart from context assembly | reserved seam |
| 0003 | PromptComposer builds a provider-agnostic PromptSpec (system+developer+context+task); the provider adapter renders it | Raw message text as prompt is not deterministic or testable | accepted (v1) |
| 0004 | No Workflow engine in v1; Plan/PlanStep = within a task, Workflow = across tasks; reserve nullable `workflowId` | A multi-task DAG is over-engineering before single-task execution works | deferred (v2+) |
| 0005 | `ResourceRef` + `ResourceResolver` port for read-side inputs only; Artifact (output) stays separate | Input references (Project, Attachment, ConnectorItem) were fragmented | reserved seam (see 0072 for connectors) |
| 0006 | Define domain event types and an EventBus port (in-process); no in-core choreography | Implicit event-driven control flow is hard to trace | reserved seam |
| 0007 | Plugin system rejected for v1; a future plugin is a bundle of implementations of existing narrow ports | "Plugin" conflates four unrelated extension types | rejected (v1) |
| 0008 | No agent runtime in v1; reserve `AgentProfile` as configuration, not a service | "Agent" is ambiguous (persona vs loop vs sub-orchestrator) | deferred runtime; seam reserved |
| 0009 | Actor/Principal identity; Session and Task reference `actorId`; one Discord user maps to one local Actor | Raw platform userId strings block a future team edition | accepted (v1) |
| 0010 | `Usage` value object on TaskRun plus a reserved TelemetryProvider port | Cost/provider/time is domain data and must be captured from run #1 | reserved seam |
| 0011 | AI-native docs: ARCHITECTURE.md (rules) + DECISIONS.md (why) required reading; AGENTS.md canonical, CLAUDE.md a thin pointer; no CODEX.md | Agents must behave correctly without re-deriving intent | accepted (v1) |
| 0012 | Role-based (not vendor-based) collaboration model: Product Owner, Chief Architect, reviewers, implementer | Charter reconciliation; no AI vendor hard-coded into governance | accepted (v1) |
| 0013 | Split Sprint 1 into thin slices (1a walking skeleton echo, 1b cognition); YAGNI on seams | The Charter's Sprint 1 lit up six stubbed components at once | accepted (v1) |
| 0014 | Minimal ContextBundle and layered PromptSpec shapes; Claude CLI invocation contract | Sprint 1b needs concrete shapes and a defined CLI run | accepted (v1) |
| 0015 | Accept that `claude -p` loads global CLAUDE.md/memory; keep neutral cwd, no `--bare`; CLI failure taxonomy | `--bare` is not usable with OAuth login | accepted (v1) |
| 0016 | Discord delivery: chunk at 1900 chars (adapter-side), bounded retry/failure handling | Discord caps messages at 2000 chars | accepted (v1) |
| 0017 | Short-term conversation memory: store both user and assistant turns per session | Follow-ups need the previous turn; minimum continuity | accepted (v1) |
| 0018 | Local project registration is a deterministic command (`REGISTER_PROJECT`), not an AI task | A user must register a project before any coding agent | accepted (v1) |
| 0019 | Gated read-only Project Analysis over an allow-list of metadata files; no repo mutation | Chat only had a top-level file-tree summary | accepted (v1) |
| 0020 | SQLite schema versioning with a forward-only migration runner on `PRAGMA user_version` | Startup `CREATE IF NOT EXISTS` + try/catch ALTER does not scale | accepted (v1, RC) |
| 0021 | Core defines a `Logger` port; core never touches `console`; composition root injects the adapter | Records the existing seam | accepted (v1, RC) |
| 0022 | Workspace Capability = filesystem read/diff; separate from a future Git Capability | Foundation for all coding capabilities; keep concerns independent | accepted (v2, 2a) |
| 0023 | CAP-002 Git Capability: read-only repository inspection via `GitProvider`, `GitManager`, local adapter | ADR-0022 left git status a stub for this | accepted (v2, 2b) |
| 0024 | CAP-003 Planning: deterministic `ExecutionPlan` is the cross-capability contract (pure data) | Every execution flow needs a reviewable blueprint before action | accepted (v2, 2c) |
| 0025 | CAP-004 Approval: `ApprovalRequest` aggregate bound to an ExecutionPlan; Aggregate Ownership Rule (each capability mutates only its own aggregate) | see ADR | accepted (v2, 2d) |
| 0026 | CAP-005 Patch: generates a PatchSet, never applies | see ADR | accepted (v2, 2e) |
| 0027 | CAP-006 Workspace Write: applies a PatchSet, Ref-gated by approval; owns `WorkspaceChange` | see ADR | accepted (v2, 2f) |
| 0028 | CAP-007 Command Execution: gated runner (allow-list, dangerous-arg and risk checks); owns `CommandExecution` | see ADR | accepted (v2, 2g) |
| 0029 | CAP-008 AI Code Generation (Codex): owns CodeGeneration + CodeProposal; proposes, never applies | see ADR | accepted (v2, 2h) |
| 0030 | CAP-009 Ollama code-generation provider behind the existing `AiProvider` port; suggest-only | see ADR | accepted (v2, 2i) |
