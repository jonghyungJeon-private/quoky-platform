# ADR-0112 쓰기 추가 2건 — 종형님 결정 시트 (2026-10-15 오후, A6 R1 묶음과 함께)

- **원문:** `DECISIONS.md`의 "ADR-0112 amendment 1"(Slack 메시지 삭제)과 "ADR-0112 amendment 2"(Jira 이슈
  생성과 되돌리기). 둘 다 **제안 상태**이고, 종형님이 정하시기 전에는 코드가 없습니다. (아키텍트 검토 반영본)
- **왜 필요한가:** 종형님이 정하신 "되돌려줘 = 원래 상태로" 규칙(A6) 때문입니다.
  - Slack에 올린 글을 되돌리려면 **그 글을 지우는 기능**이 필요합니다. 이 기능은 R3(외부 쓰기) 단계에 들어가기
    전에 있어야 합니다.
  - Jira 이슈 만들기는 R4 단계이고, 되돌리기(삭제, 안 되면 닫기)도 함께 정해야 합니다.
- **답하는 법:** 각 줄에 "권장대로" 또는 다른 답을 한 줄로 주시면 됩니다. 모두 권장대로면 "전부 권장대로" 한 마디면
  충분합니다.

## 용어 풀이

| 용어 | 뜻 |
|---|---|
| 승인 카드 | 실제로 보내기 전에 "정확히 이 내용을 이곳에 보냅니다"를 보여 주는 미리보기입니다. "승인" 뒤에 실행 문구까지 보내야 실행됩니다 |
| 최고 단계 승인(CRITICAL) | 내용이 고정된 1회용 승인입니다. 내용이 하나라도 바뀌면 무효가 됩니다 |
| 영수증(receipt) | Quoky가 외부에 쓴 기록입니다(무엇을, 어디에, 성공 여부). 내용 원문은 저장하지 않습니다 |
| 불확실(UNCERTAIN) | 네트워크가 끊겨 실제로 됐는지 모르는 경우입니다. 중복을 막으려고 **자동으로 다시 시도하지 않습니다** |
| 허용 목록 | 쓰기를 허락한 곳만 적은 목록입니다. 지금은 Slack `#quoky-test`와 Jira `BE` 프로젝트입니다 |
| OAuth 권한(scope) | 앱 토큰에 붙은 허락 범위입니다. 새로 추가하려면 종형님이 직접 Slack 앱이나 Atlassian 설정을 바꾸셔야 합니다(Strict) |
| 끼어든 명령 | 메일, 슬랙, 문서 **내용 안에** 적힌 "이거 지워줘" 같은 문장입니다. 이런 문장은 절대 실행 대상이 되지 않습니다 |

## 공통 규칙 (두 기능 모두)

- **되돌리기는 같은 대화 안에서만 됩니다.** 방금 한 일은 10분 안에, Quoky의 확인 메시지에 답장하면 30분 안에 되돌릴
  수 있습니다. `새 대화` 뒤나 다른 메신저(텔레그램과 디스코드)에서는 되돌릴 대상이 없다고 답합니다.
- **자연어 동작 스위치(`QUOKY_NL_ACTIONS`) 단계별 동작:**
  - `off`이면 기록이 남지 않아 되돌리기가 없습니다. 이때는 Slack이나 Jira에서 직접 지우셔야 합니다.
  - `external` 단계에서만 외부 되돌리기(삭제, 닫기)가 실제로 동작합니다.
- **되돌리기 카드에는 출처 표시가 붙습니다.** "대상은 Quoky가 보낸 기록(영수증)에서 가져왔어요"라는 문구가 들어갑니다.
- **실행 문구에는 늘 시스템 이름이 들어갑니다.** "삭제 실행"만 보내면 무엇을 지우는지 알 수 없으므로 받지 않습니다.

## 1. Slack 메시지 삭제 (R3 전에 필요)

**한 줄 요약.** Quoky가 직접 올린 Slack 글만, 같은 대화에서 "되돌려줘"로만 지웁니다. 지울 대상은 Quoky의
영수증에서 가져오고, 사람이 적은 링크나 번호로는 지우지 않습니다. 지우기 전에도 최고 단계 승인을 거치고,
**"Slack 삭제 실행"**(또는 "슬랙 삭제 실행")을 보내셔야 실행됩니다.

- **새 권한이 필요 없습니다.** 지금 쓰는 봇 토큰 권한(`chat:write`)으로 자기 글은 지울 수 있습니다.
- **접속 대상도 그대로입니다.** 같은 `slack.com`이라 보안 허용 목록(ADR-0121)을 바꾸지 않습니다.
- **기간 제한은 따로 두지 않습니다.** 승인 유효시간 때문에 삭제는 어차피 글을 올린 뒤 약 90분 안에만 일어납니다.
- **알아 두실 점:**
  - 글에 스레드 답글이 있으면, 답글은 남고 원글 자리에 "삭제된 메시지"가 보입니다.
  - 이미 손으로 지운 글이면 "이미 지워졌어요"라고만 답합니다.

## 2. Jira 이슈 만들기와 되돌리기 (R4)

**한 줄 요약.** "BE 프로젝트에 '로그인 오류 확인' 이슈 만들어줘"라고 하시면, 최고 단계 승인 뒤
**"Jira 이슈 생성 실행"**을 보내셔야 이슈가 하나 만들어집니다. "되돌려줘"라고 하시면, 만든 뒤 아무 변경이 없는
이슈일 때만 **"Jira 이슈 삭제 실행"**으로 지웁니다. 그렇지 않으면 대신 닫을지 여쭙니다. ("지라 …"로 보내셔도 됩니다.)

- **새 설정값 하나:** `QUOKY_CONNECTOR_WRITE_JIRA_ISSUE_TYPE`(이슈 유형, 기본 `Task`)가 생깁니다.
- **새 OAuth 권한은 필요 없습니다.** 지금 쓰는 Atlassian API 토큰은 종형님 계정의 권한으로 동작합니다.
- **필요한 Jira 권한:**
  - 만들기: `BE`의 *이슈 만들기* 권한이 필요합니다(아마 이미 있습니다).
  - 삭제: *이슈 삭제* 권한이 필요합니다. 보통 프로젝트 관리자만 가지고 있습니다.
  - 권한을 새로 받는 일은 Jira 관리자에게 요청할 일이라 Strict 항목입니다. 권장안은 **지금은 요청하지 않는 것**입니다.
- **J-9를 권장대로 하시면 생기는 점(꼭 확인해 주세요):**
  - 삭제 권한이 없으면 Jira 되돌리기는 **원래 상태로 돌아가지 않습니다.** 이슈는 지워지지 않고 "닫힌" 채로 남습니다.
  - 라이브 UAT(U22)에서도 실제 삭제는 시험하지 못합니다.
  - UAT로 만든 이슈는 `BE`에 닫힌 이슈로 남습니다.
- **"변경 없음"의 기준은 엄격합니다.** 변경 기록이 하나라도 있거나, 댓글, 첨부, 링크, 외부 링크, 하위 작업, 작업
  기록이 있으면 지우지 않고 "이미 변경된 이슈라 지우지 않을게요. 대신 닫을까요?"라고 여쭙니다.
  - 누가 바꿨는지는 따지지 않습니다.
  - `BE`에 이슈가 만들어지자마자 자동으로 담당자나 라벨을 붙이는 Jira 자동화가 있다면, 모든 되돌리기가 "닫기"로
    처리됩니다.
- **중복 방지:** Jira에는 "같은 요청이면 한 번만 만들기" 기능이 없습니다.
  - 그래서 Quoky는 만든 이슈에 **눈에 보이지 않는 표식**을 붙이고, 영수증에 적힌 이슈 키와 함께 확인합니다.
  - 네트워크가 끊겨 됐는지 모를 때는 다시 만들지 않습니다. 대신 표식으로 한 번 찾아보고 "만들어졌어요: BE-123" 또는
    "아직 못 찾았어요"라고 알려 드립니다.
- **끼어든 명령은 막힙니다.** 메일이나 Jira 내용 안의 "이슈 만들어줘"는 실행되지 않습니다. 이슈 제목은 종형님이 **그
  턴에 직접 쓰신 말 그대로**만 씁니다.
